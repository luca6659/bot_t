# Бот для продажи 3D-игрушек

Telegram-бот на TypeScript и grammY: каталог с фото-галереями и поиском, хиты и новинки, корзина, своя модель по фото, счета и чеки, статусы заказа, анонимная переписка с покупателем через темы и админка прямо в Telegram.

Одна моделька = одна цена, без размеров и цветов. У модельки несколько фото (хранятся как Telegram file_id), метки «🔥 Хит»/«🆕 Новинка» и наличие «в наличии/под заказ». Все экраны редактируются на месте, чат не засоряется; где нет своего фото, показывается баннер-заглушка.

## Подготовка в Telegram

1. В [@BotFather](https://t.me/BotFather) создать бота командой `/newbot` и сохранить токен.
2. Создать группу для админов и включить в её настройках **Темы** (Topics).
3. Добавить бота в группу и сделать администратором с правами **управлять темами** и **закреплять сообщения**.
4. Написать в группе `/chatid`: бот пришлёт ID группы и твой личный ID.

## Запуск на своём компьютере

Нужен Node.js 22 или новее. База поднимается сама в папке `.data`, бот работает через long polling.

```bash
npm install
cp .env.example .env
```

В `.env` заполнить `BOT_TOKEN`, `ADMIN_GROUP_ID` и `ADMIN_IDS`, затем:

```bash
npm run dev
```

## Запуск в облаке

Подойдёт любая платформа с Node.js или Docker (Railway, Timeweb Cloud Apps и т.п.) и база PostgreSQL (например, Neon). В проекте есть `Dockerfile`.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | токен бота |
| `ADMIN_GROUP_ID` | ID группы админов |
| `ADMIN_IDS` | ID админов через запятую; пусто — админка у всех в группе |
| `DATABASE_URL` | адрес PostgreSQL |
| `WEBHOOK_URL` | публичный адрес сервиса, например `https://bot.example.com` |
| `WEBHOOK_SECRET` | длинная случайная строка из букв и цифр |
| `NODE_ENV` | `production` (в Dockerfile уже задано) |

Таблицы создаются при старте. Проверка работы: `GET /healthz`. Запускать нужно **один экземпляр**: очередь апдейтов и лимиты хранятся в его памяти.

## Первая настройка

В группе написать `/admin`, затем:

1. **Тексты → Баннер меню** — фото главного меню и заглушка для экранов без своих фото.
2. **Тексты → Реквизиты для оплаты.** Пока их нет, бот предупреждает админов в теме заказа.
3. **Тексты → Адрес и часы самовывоза**, при желании **О нас** и **Доставка и оплата**.
4. **Тексты → Курьер.** Единая цена доставки или `-`, чтобы считать её вручную для каждого заказа.
5. **Категории** (название, обложка, порядок), затем **Модельки**: название → описание → фото (до 10, альбомом или по одному) → категория → цена → наличие → метки.

## Как идёт заказ

`Новый → Ждёт оплаты → Чек на проверке → Оплачен → Собирается (у своей модели — В печати) → Передан курьеру / Ждёт самовывоза → Выполнен`, отменить можно на любом шаге до выполнения.

- Оформление: имя → телефон (кнопка «Поделиться контактом») → 🚕 курьер (адрес текстом или геолокацией) / 🏠 самовывоз → комментарий → подтверждение. На каждом шаге «⬅️ Назад» и «❌ Отмена».
- Покупатель получает уведомление с фото модельки о каждом статусе, кроме «Новый».
- «Новый» означает одно из двух: своя модель ждёт оценки или курьерская доставка ждёт расчёта. При самовывозе и при единой цене курьера счёт уходит сразу.
- Оплата ручная: реквизиты + фото чека, подтверждение кнопкой. Модуль оплаты (`src/modules/payment/`) изолирован: для ЮKassa реализуется тот же интерфейс `PaymentProvider` и подставляется в `create-bot.ts`.
- Своя модель: описание + до 10 фото-референсов → пожелания и сроки → продавец отвечает ценой, сроком и, при желании, фото-рендером. У покупателя кнопки «✅ Согласен», «💬 Обсудить», «❌ Отказаться». Лимит — 5 заявок в сутки.

## Переписка

Всё, что покупатель пишет боту вне диалогов, приходит в его тему. Обычное сообщение админа в этой теме бот копирует покупателю от своего имени, поэтому автора покупатель не видит. **Любое сообщение в теме уходит покупателю**, кроме команд и ввода, который бот сам запросил. Обсуждать заказ между собой лучше в теме General.

В теме закреплена карточка клиента: имя, телефон, последние заказы со статусами, кнопки смены статуса актуального заказа и бан. Новые заказы, чеки и заявки дублируются в служебную тему «🔔 Заказы», сбои — в «⚠️ Ошибки». Обе темы бот создаёт сам.

## Разработка

```bash
npm test
npm run typecheck
```

Тесты проходят все сценарии на настоящем коде бота и встроенном Postgres, вместо Telegram работает имитация, которая проверяет его ограничения (разметка, длина текста, размер данных кнопки).

Структура: `src/modules/*` разбит по доменам, внутри слои Handler → Service → Repository. Сборка всех частей находится в `src/bot/create-bot.ts`, запуск в `src/app.ts`, тексты в `src/i18n/texts.ts`.
